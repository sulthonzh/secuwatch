# cmdseek - Fast Recursive Command Search CLI with AI-Powered Suggestions

## One-Liner
A lightning-fast command search CLI that learns from your usage patterns and suggests commands before you finish typing, reducing the time spent searching documentation or remembering complex commands.

## Problem (with evidence URLs)

Developers waste significant time searching for commands across:
- CLI tools (`grep`, `find`, `sed`, `awk`)
- Git commands (`git rebase --interactive`, `git log --oneline --graph`)
- Package manager commands (`npm install --save-dev`, `pip install -r requirements.txt`)
- Docker commands (`docker run --rm -p 8080:8080`)
- VS Code extensions and editor commands
- Custom scripts and aliases

**Evidence:**
- Stack Overflow: ~200k questions tagged "command-line"
- HN: "I waste hours every week looking up the same git commands" (multiple posts)
- Twitter: Devs sharing "cheat sheets" as coping mechanism for command overload

| `navi` | 18k⭐ | 2024 | Interactive cheat sheets, no search |

**Gaps:**
1. **No learning from usage patterns** - All existing tools are static lookup tables
2. **No proactive suggestions** - Tools don't anticipate what you might need based on context
3. **No fuzzy matching with intent recognition** - Can't handle "restart docker container" vs "docker restart container"
4. **No cross-tool command unification** - Can't search across git, npm, docker, etc. together

## Our Angle

**cmdseek** is different because it:

1. **Learns from your actual usage** - Builds a personal command usage profile
2. **AI-powered intent recognition** - Understands natural language queries like "restart my web server"
3. **Context-aware suggestions** - Suggests commands based on current directory, git branch, open files
4. **Progressive enhancement** - Starts with basic search, adds learning as you use it
5. **Cross-tool search** - Searches across all CLI tools, not just one category

## Security Assessment

**Attack Surface:** 
- File system access for reading usage history
- Network access for AI suggestions (optional)
- Command execution (via generated commands)

**Data Handled:**
- Command history patterns
- Directory/workspace context
- Personal usage preferences

**Controls:**
- Local-only mode (no cloud AI)
- Configurable data retention
- Command sandboxing before execution
- Explicit confirmation for generated commands

**CVE Check:**
- Similar tools like `navi` and `tldr` have no major CVEs
- Command execution tools like `xargs` have historical vulnerabilities but well-understood attack vectors
- Local-only AI models avoid cloud data exposure risks

**Security Level:** 🔒 **Medium** - Requires careful command execution handling but no sensitive data exposure.

### API/CLI Examples

```bash
# Basic search
$ cmdseek "restart docker container"
🎯 SUGGESTED: docker restart <container_id>
🎯 ALTERNATIVE: docker-compose restart web
💡 RECENTLY USED: docker restart my-app-container

# Context-aware search (in git repo)
$ cmdseek "show last commits"
🎯 SUGGESTED: git log --oneline -10
🎯 ALTERNATIVE: git log --graph --all --oneline
💡 YOU USE: git log --pretty=format:"%h %s"

# Learning from usage
$ cmdseek "find js files"
🎯 SUGGESTED: find . -name "*.js" -type f
🎯 LEARNED: You prefer "-type f" over broader search

# Cross-tool search
$ cmdseek "install package"
🎯 CONTEXT: Node.js project (package.json found)
🎯 SUGGESTED: npm install <package_name>
🎯 ALTERNATIVE: yarn add <package_name>
💡 RECENTLY: npm install --save-dev prettier
```

### Technology Stack
- **Runtime**: Node.js with TypeScript
- **AI**: Local Llama.cpp model or OpenAI API (configurable)
- **Database**: SQLite for usage patterns (local-only)
- **CLI**: Commander.js + Readline integration
- **Search**: Fuse.js for fuzzy matching
- **Config**: JSON with schema validation
