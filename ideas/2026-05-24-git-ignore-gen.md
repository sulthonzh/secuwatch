# git-ignore-gen

**One-Liner:** Interactive CLI that scans your project for untracked files and suggests .gitignore patterns based on actual project state.

## Problem (with evidence URLs)

Developers struggle to create effective .gitignore files that match their specific project needs. Template-based tools like github/gitignore (174k⭐) provide generic patterns that often miss project-specific file types.

**Key Pain Points:**
- Manual .gitignore creation is tedious and error-prone
- Template repositories don't account for unique file patterns in your project
- `git status` shows untracked files that should be ignored, but requires manual rule creation
- No existing tool auto-detects ignore patterns from actual untracked files

**Evidence of Demand:**
- 911+ repositories on GitHub related to gitignore (github.com/topics/gitignore)
- Multiple interactive tools exist: TejasQ/add-gitignore (interactive CLI), simonwhitaker/gibo (Go, 2026 updated), reemus-dev/gitnr (Rust, 2026 updated)
- Stack Overflow questions about gitignore patterns consistently show users struggling with project-specific scenarios

## Our Angle

**Project-aware .gitignore generation** that learns from your project's actual state:

1. **Smart Scanning:** Analyzes `git status` to identify untracked files and directories
2. **Pattern Intelligence:** Suggests ignore rules based on file extensions, naming patterns, and directory structures
3. **Interactive Selection:** Presents detected patterns with explanations and allows selective inclusion
4. **Continuous Learning:** Remembers patterns across projects for smarter suggestions
5. **Template Enhancement:** Combines auto-detected patterns with curated templates

**Differentiation:** While other tools let you "choose from templates", we help you "discover what you should ignore" based on your actual project state.

## Security Assessment

- **External Dependencies:** Node.js filesystem APIs, git CLI
- **Network Access:** None (offline-first)

- Validates git repository status before operations
- Sanitizes generated patterns to prevent command injection

**CVE Check:** No known CVEs in gitignore-related tools. All operations are file-system local.

### Pattern Detection Logic

```typescript
interface PatternSuggestion {
  pattern: string;
  confidence: number; // 0-1 based on file analysis
  description: string;
  category: 'build' | 'dependencies' | 'system' | 'project-specific';
  examples: string[]; // Example files that match
}

class PatternDetector {
  detectFromGitStatus(): PatternSuggestion[] {
    const untrackedFiles = this.parseGitStatus();
    return [
      this.detectNodeModules(untrackedFiles),
      this.detectBuildArtifacts(untrackedFiles),
      this.detectSystemFiles(untrackedFiles),
      this.detectProjectSpecific(untrackedFiles)
    ];
  }
}
```

## Deep Dive Finding

**Critical Insight:** The template-based approach creates a "cold start" problem - developers must know what they want to ignore before they can ignore it. Project-aware scanning reverses this by showing them what they should ignore based on what they're already tracking. This creates immediate value that template tools cannot match.

**Market Validation:** The recent activity in gitignore tools (gibo updated May 2026, reemus-dev/gitnr updated May 2026) indicates sustained demand. However, all remain template-based, suggesting the auto-detection gap remains unaddressed.

**Key Differentiator:** While competitors focus on "better templates", we focus on "smarter detection" - the tool that understands what you actually need, not what you think you need.
