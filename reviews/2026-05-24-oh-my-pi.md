## Findings

### 🔴 [Security/MEDIUM-HIGH] Path Traversal via bash.cwd Parameter

**Location:** `packages/coding-agent/src/tools/bash.ts:402`
**Issue Filed:** https://github.com/can1357/oh-my-pi/issues/1331

The `bash` tool's `cwd` parameter accepts arbitrary absolute paths without validating that they reside within the intended workspace boundary. While path normalization prevents `../` escapes via `resolveToCwd`, absolute paths like `/etc`, `/tmp`, or `~/.aws` bypass containment entirely.

**Attack Vector:**
```json
{"command": "cat /etc/passwd", "cwd": "/"}  // Succeeds
{"command": "ls ~/.ssh", "cwd": "/home/user"}  // Succeeds
```

**Impact:**
- Path traversal to arbitrary system directories
- Information disclosure (system files, credentials, API keys)
- Workspace isolation bypass
- Lateral movement in multi-tenant or CI environments

**Root Cause:**
`path-utils.ts:resolveToCwd()` correctly normalizes paths but has no workspace boundary enforcement:
```typescript
export function resolveToCwd(filePath: string, cwd: string): string {
  // ... normalization logic ...
  if (path.isAbsolute(expanded)) {
    return expanded;  // ❌ No boundary check
  }
  return path.resolve(cwd, expanded);
}
```

**Suggested Fix:**
Add boundary validation in `bash.ts:execute()` after resolving `commandCwd`:
```typescript
const resolvedWorkspace = path.resolve(this.session.cwd);
const resolvedCwd = path.resolve(commandCwd);
const relativePath = path.relative(resolvedWorkspace, resolvedCwd);

if (relativePath.startsWith("..") || (path.isAbsolute(commandCwd) && commandCwd !== resolvedWorkspace)) {
  throw new ToolError(`Working directory "${commandCwd}" is outside workspace boundary`);
}
```

For intentional broader access, add a setting like `bash.allowEscapingWorkspace: boolean` (default `false`).

**Mitigation Notes:**
- The `iso` crate (APFS/overlayfs/reflink isolation) protects subagent worktrees but NOT the main session
- Other tools (`read`, `write`, `edit`, `search`, `eval`) may have the same vulnerability and should be audited
- Consider adding a global workspace boundary setting for all filesystem tools

## Conclusion

OhMyPi is a well-architected coding agent with 32 tools and ~27K lines of Rust core. However, the main session lacks workspace boundary enforcement for the bash tool, allowing path traversal to arbitrary system directories. This is a significant security gap that should be addressed by adding boundary validation to all filesystem-accessing tools.

The issue has been filed with concrete reproduction steps, impact analysis, and a fix proposal. Maintainers should also audit other tools (`read`, `write`, `eval`) for similar vulnerabilities.
