## Review Findings

### 🔒 Security

#### 1. **CRITICAL: Path Traversal in Browser Download** - `src/cli/handlers/browser-interact.ts`
- **File**: `src/cli/handlers/browser-interact.ts:312-318`
- **Issue**: The `download` command accepts an arbitrary `path` parameter from user input without any validation or sanitization.
```typescript
download: async ({ flags, client, cwd, json }) => {
  const selector = getRequiredStringFlag(flags, 'selector')
  const path = getRequiredStringFlag(flags, 'path')
  const target = await getBrowserCommandTarget(flags, cwd, client)
  const result = await client.call<unknown>('browser.download', { selector, path, ...target })
  printResult(result, json, () => `Downloaded to ${path}`)
}
```
- **Impact**: An attacker can use path traversal sequences (`../`, absolute paths) to write files anywhere on the filesystem, potentially overwriting system files, placing malware, or accessing sensitive data.
- **Severity**: HIGH
- **Suggested Fix**: Validate that `path` is within a safe download directory (e.g., `~/Downloads/orca/`), reject absolute paths and path traversal sequences, and create subdirectories as needed within the sandbox.

#### 2. **HIGH: Unrestricted JavaScript Evaluation in Browser** - `src/cli/handlers/browser-nav.ts`
- **File**: `src/cli/handlers/browser-nav.ts:76-81`
- **Issue**: The `eval` command accepts arbitrary JavaScript expressions from user input without any sanitization or sandboxing restrictions.
```typescript
eval: async ({ flags, client, cwd, json }) => {
  const expression = getRequiredStringFlag(flags, 'expression')
  const target = await getBrowserCommandTarget(flags, cwd, client)
  const result = await client.call<BrowserEvalResult>('browser.eval', { expression, ...target })
  printResult(result, json, (v) => v.result)
}
```
- **Impact**: This allows execution of arbitrary JavaScript in the browser context, which can be used to steal cookies, modify DOM, make unauthorized requests, extract sensitive data from the page, or perform XSS-like attacks.
- **Severity**: HIGH
- **Suggested Fix**: Implement a JavaScript expression whitelist, use a sandboxed evaluation context with restricted APIs, require explicit user confirmation for eval commands, or deprecate the feature in favor of safer interaction primitives.

#### 3. **MEDIUM: Insufficient Input Validation for Cookie Values** - `src/cli/handlers/browser-cookie.ts`
- **File**: `src/cli/handlers/browser-cookie.ts:24-58`
- **Issue**: Cookie values (`name`, `value`, `domain`, `path`) are accepted without any validation for XSS, injection, or malformed data.
```typescript
const name = getRequiredStringFlag(flags, 'name')
const value = getRequiredStringFlag(flags, 'value')
const domain = getOptionalStringFlag(flags, 'domain')
const path = getOptionalStringFlag(flags, 'path')
```
- **Impact**: Could be used to inject malicious cookies, cause browser inconsistencies, or interfere with legitimate cookie handling.
- **Severity**: MEDIUM
- **Suggested Fix**: Validate cookie names and values according to RFC 6265, reject control characters, limit value lengths, and validate domain/path formats.
