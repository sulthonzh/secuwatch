## Summary
Tirith is a terminal security scanner for developers and AI agents. It intercepts homograph URLs, pipe-to-shell attacks, ANSI injection, obfuscated payloads, data exfiltration, and malicious AI skills/configs before they execute. Written in Rust with a well-structured workspace (tirith + tirith-core crates).

## Review Findings

### 🔒 Security
- **CLEAN — good practices overall**: Webhook env var expansion properly restricts to `TIRITH_*` prefix only. SSRF validation on webhook URLs. Credential redaction before webhook payload delivery. Template injection mitigated by JSON validation fallback.
- **Finding (filed)**: Silent swallowing of rule panics during batch file scans means a malicious file could crash a rule and be silently excluded from scan results.

### 🐛 Bugs
- **Finding (filed)**: `follow_redirects()` returns `Some(current)` when redirect chain exceeds MAX_REDIRECTS, contradicting `resolve_shortened_url()` docs that say it returns `None`. This allows attackers to evade short URL expansion with >10 redirect chains.

### ⚡ Performance
- Short URL cache uses lazy eviction (only at >1024 entries). Expired entries linger between eviction passes. Minor — not filed.

### 📐 Architecture
- Excellent crate separation (tirith-core for logic, tirith for CLI)
- Effect-free core design: network/filesystem mutations in CLI layer, testable core
- Install method detection is thorough and honest (defaults to Unknown when unsure)
- Template-based webhook payloads with JSON validation fallback — good defense-in-depth
- `catch_panic_scanning` is good for robustness but needs better reporting (filed)
