## Security Findings

### [MEDIUM] Filename Sanitization Does Not Strip Control Characters

**File:** `apps/api/plane/utils/path_validator.py`
**Issue:** The `sanitize_filename()` function strips null bytes but does not remove other control characters (tab `\t`, newline `\n`, carriage return `\r`, etc.) from user-provided filenames.

**Attack Vector:**
1. User uploads file with filename containing control characters
2. Filename is used directly in S3 object key: `{workspace_id}/{uuid}-{filename}`
3. Control characters persist in storage

**Impact:**
- Storage inconsistencies across S3 clients and AWS console
- Display issues in UI and logging tools
- API compatibility problems with some S3-compatible systems
- Security audit difficulty - control characters obfuscate actual filenames in logs
- Potential CSV parsing issues if filenames are exported (though Plane has CSV injection mitigations)

**Root Cause:**
```python
def sanitize_filename(filename):
    # ...
    filename = filename.replace("\x00", "")  # Only strips null bytes
    # ... no control character handling
```

**Fix:**
```python
# Strip all ASCII control characters (0-31, 127)
filename = "".join(char for char in filename if not (ord(char) < 32 or ord(char) == 127))
```
